# 163 — Add an under-development warning banner to the top of the project site
Issue: #163

## Asked
Anyone landing on the project's GitHub Pages site should see, before anything else, a
clear warning that t-workflow is still under heavy development and not recommended for
use before version 1.0, and that the site itself is currently AI-generated. Add a
visually distinct warning box at the very top of the site (above the existing header)
carrying this text verbatim:

> This project is still under heavy development and we don't suggest you use it until
> version 1.0 is released. For example this site is currently generated by AI and as
> you would expect it is currently mainly AI slop

The site is a static single page under `site/` (`index.html`, `styles.css`,
`script.js`, `favicon.svg`), deployed to GitHub Pages by `.github/workflows/pages.yml`
on every push to `main`. It has a light and a dark theme (`data-theme` on `<html>`) and
no build step or external dependencies.

## Done when
- `site/index.html` contains the warning text above verbatim, in a box that is the
  first visible element of the page — above the `<header class="site-header">`, not
  inside it, and not inside `<main>`: `grep -c "under heavy development"
  site/index.html` returns at least 1, and the match occurs before the first `<header`
  in the file.
- The box is marked up as an alert for assistive technology (`role="alert"` or
  equivalent) and reads as a warning visually: a distinct warning colour (amber/yellow
  family), a warning icon or label, readable contrast in both the light and dark
  themes. Visual judgment is a human's: open `site/index.html` in a browser, toggle the
  theme, and confirm the box is obvious and legible in both.
- The box is always visible on page load, with no dismiss/close control and nothing
  stored in `localStorage` for it.
- No new external stylesheet, script, font, or CDN dependency is introduced:
  `grep -nE 'https?://' site/index.html site/styles.css site/script.js` shows no new
  hosts beyond those already present on `main`.
- The existing header, hero, navigation, theme toggle, and reading-progress bar
  continue to work: the warning box does not overlap or hide the sticky header once the
  page is scrolled.
- `./.t-workflow/scripts/consistency-check.sh` passes.

## Explicitly not
- No change to the wording of the warning — it is used exactly as given.
- No dismissable/closable banner, cookie, or remembered state.
- No change to `README.md`, the installer, the skills, or any other project
  documentation — this is the Pages site only.
- No change to `.github/workflows/pages.yml` or any other CI/deploy configuration.

## Decisions made along the way
- The banner is a plain in-flow block placed between the reading-progress bar and the
  sticky header, not fixed or sticky itself. Scrolling moves it off-screen and the
  header then sticks at the top exactly as before, so no header offset or
  `site/script.js` change was needed (agent, 2026-09-07).
- Warning colours are three new theme tokens (`--warn-bg`, `--warn-line`,
  `--warn-ink`) alongside the existing `--warn`, defined for both themes, rather than
  reusing the muted callout styling — the callout is a secondary aside, this must be
  the loudest thing on the page (agent, 2026-09-07).
- The visible label reads "Warning" with a decorative ⚠ glyph hidden from assistive
  technology; the container carries `role="alert"`. The verbatim text sits in its own
  `<p>` so nothing is interleaved with it (agent, 2026-09-07).
