Reference · Skills

Nine commands, one per stage.

Each skill lives as a SKILL.md file under .claude/skills/<name>/. None of them name a vendor directly — every tracker or forge action below is a named operation that docs/adapters/TRACKER.md and docs/adapters/FORGE.md map to a real command (GitHub by default). This page lists, for each skill, what it does, and exactly which of those operations and which scripts it calls.

The five-stage core path

Every task moves through these, start to merge.

/t-openEntrance

Turns a converged conversation into tracker issues — the only way work starts. Makes the shape judgment: one task (fits one PR), an initiative (a tracking issue plus clear child tasks), or an initiative whose only child is a design task when the decomposition isn't known yet. Creates no branch, record, or code.

  • Ensures labels exist, then creates the issue(s) with a Goal / Done when / Scope / Non-goals body.
  • Applies exactly one classification label (bug, enhancement, documentation, question) to every task issue, plus any already-existing project-specific labels whose fit is unambiguous.
  • Links a tracking issue's children and any named blockers immediately after creation — native relations, not body text.
  • Opens a same-turn issue for any deferred Non-goal, tagged Split from: #<id> (the one relationship GitHub has no native field for).

Tracker/forge operations: tracker:ensure-labels, tracker:create, tracker:label, tracker:list-labels, tracker:set-parent, tracker:add-blocker.

Scripts: none directly — the issue-form mirrors of this skill's body template live under .github/ISSUE_TEMPLATE/.

/t-planBefore protected work

Sharpens an existing issue into a bounded plan, without implementing anything. Optional in general, but required before any change to a protected surface (CONSTITUTION.md §3) — /t-work refuses without one once it discovers the diff needs it.

  • Writes one ## Plan section onto the issue body: Allowed paths, Risks / constraints, and a Validation block splitting agent_checks (each tagged implementation, review, or either) from human_checks.
  • On a re-plan, replaces the section wholesale — an issue carries exactly one, always — and the report quotes the previous Allowed paths verbatim so the task record can capture why they changed.
  • Runs a scope-overlap check against every other open issue, naming any overlap rather than silently proceeding.

Tracker/forge operations: tracker:view, tracker:edit-body, tracker:list-open.

Scripts: none called directly by this skill; its output is what scripts/check-plan-gate.sh later checks for.

/t-workImplementation

One invocation, start to draft PR, in the current checkout. Checks gates, resolves or creates the task branch, writes the task record, implements within the declared scope, runs the checks, and opens a draft pull request. Also runs narrow fix passes when a review left blocker/high findings.

  • Phase 1 (gates): reads the issue and its plan; refuses if any blocker isn't closed as completed; checks the declared scope against scripts/protected-paths.sh and stops for /t-plan if a protected path has no plan; resolves the wip/<id>-<slug> branch idempotently.
  • Phase 2 (the work): stays inside Allowed paths / Scope; updates the record with decisions and deviations as they happen.
  • Phase 3 (checks and PR): runs the plan's implementation/either checks (or AGENTS.md §Checks with no plan); re-checks protection against the actual diff; commits, pushes, and opens the draft PR titled [<id>] <issue title>.

Tracker/forge operations: tracker:view, tracker:list-blockers, forge:pr-find-by-task, forge:pr-reviews, forge:pr-create-draft.

Scripts: scripts/protected-paths.sh (twice — expected scope, then actual diff), ./scripts/consistency-check.sh (part of the standing check set).

/t-reviewCold review

One bounded stage: reads the PR's diff in isolation from whoever implemented it, and posts findings plus an explicit readiness verdict. Required before shipping a protected surface; never fixes anything itself.

  • Resolves the PR from the task id, then establishes isolation — a fresh session, a read-only subagent, or (only for a tiny, unprotected change) the same session, recorded either way.
  • Checks scope, record honesty, constitution conflicts, unexplained removals, and the promotion rule; for a document deliverable, also consistency, ambiguity, and completeness.
  • Runs the plan's review/either checks, then posts one review: an isolation: line, findings ordered blocker/high/medium/low, a ## Pending human checks section, and a readiness: ready or readiness: not-ready verdict line.

Tracker/forge operations: forge:pr-find-by-task, forge:pr-files, forge:pr-diff, forge:pr-view, forge:pr-reviews, forge:pr-review.

Scripts: scripts/protected-paths.sh --stdin (deciding protection and the severity of any drift), ./scripts/consistency-check.sh for a document deliverable.

/t-shipMerge

The only path to main. Checks every precondition, then stops to ask the human to confirm the merge, and only then squash-merges with a commit written from the task record.

  • Preconditions: decides protection from the PR's real files; requires a plan and, on a protected surface, a current cold review with readiness: ready and an isolation that isn't same session; checks CI and mergeability; confirms the local branch tip matches the PR's pushed head; confirms the record is in the diff; carries forward any pending human checks.
  • Marks the PR ready, then asks one confirmation gate showing the evidence — review verdict, CI state, diff summary, pending human checks.
  • On confirmation, squash-merges with a self-contained subject/body built from the record, closes the issue as completed, and (for a driven initiative's aggregate PR) writes one Task: #<id> line per included child.

Tracker/forge operations: forge:pr-find-by-task, forge:pr-files, forge:pr-reviews, forge:pr-checks, forge:pr-view, forge:pr-ready, forge:pr-draft, forge:pr-merge, forge:pr-approval, tracker:view, tracker:close-done, tracker:auto-close-on-merge.

Scripts: scripts/protected-paths.sh --stdin over the PR's own changed files.

Supporting commands

Driving an initiative, cancellation, template sync, and status.

/t-driveOptional

The one explicitly-invoked exception to "nothing auto-chains": walks an initiative's children to completion on one shared integration branch (wip/<initiative-id>-integration), then stops once for a human's confirmation on a single PR to main.

  • Branches each eligible child from the integration branch, runs /t-plan (if needed), /t-work, and /t-review exactly as they run standalone, retargeting the child's draft PR onto the integration branch.
  • A readiness: ready review authorizes merging that child into the integration branch — never into main. A failing child gets exactly one bounded retry (/t-work's Fix mode), then is excluded — never auto-merged, never auto-cancelled.
  • Once every child is merged, excluded, or excluded by cascade, opens one aggregate PR to main and runs an ordinary /t-review on it before naming /t-ship.

Tracker/forge operations: tracker:view, tracker:list-children, tracker:list-blockers, forge:pr-set-base, forge:pr-ready, forge:pr-merge, forge:pr-create-draft — plus every operation /t-plan, /t-work, and /t-review use internally, since it calls them directly rather than reimplementing them.

Scripts: scripts/protected-paths.sh, when deciding whether a child needs a plan.

/t-cancelTerminal exit

The pipeline's only non-merge exit. Records why the work is being abandoned and forces an explicit decision on every dependent, child, and parent issue — gathered before the confirmation gate, acted on only after it — then closes the PR and deletes the branch.

  • Refuses on a merged task, a "not now" (that's a blocked-by dependency, not a cancellation), or a supersession with no successor named.
  • Phase 2 gathers every neighbour's disposition (dependents, parent, children, spun-off exclusions) without acting; Phase 3 is one confirmation gate naming what will be destroyed.
  • Phase 4 closes the PR (deleting its branch), then executes every neighbour disposition gathered earlier, and closes the issue carrying the reason in the close comment.

Tracker/forge operations: tracker:view, tracker:list-blocking, tracker:list-children, tracker:list-open, tracker:ensure-labels, tracker:label, tracker:close, tracker:remove-blocker, tracker:add-blocker, tracker:remove-parent, tracker:comment, forge:pr-find-by-task, forge:pr-close.

Scripts: none called directly — a stale local worktree or branch left behind is left alone permanently (ADR-005); nothing cleans it up automatically.

/t-updateOptional

For a repo generated from this template: syncs its template-owned files to a pinned release, preserving local content and applying pending migrations, landed as one ordinary pipeline task. See the Migrations page for the full mechanism.

  • Reads the current pin (.template-manifest.json), fetches the target tag into a scratch clone, and refuses outright if any currently-owned file has drifted from what the manifest recorded.
  • Computes what would change, gates on a human's confirmation, then — only after that — opens the task's own issue, branch, and record.
  • Applies file changes and pending migrations in order, writes the new manifest, and runs /t-work Phase 3 verbatim (checks, commit, draft PR).

Tracker/forge operations: tracker:create (its own task issue) — everything after that reuses /t-work Phase 3's own operations.

Scripts: scripts/check-manifest.sh (--hash-file and verify mode), scripts/template-owned-paths.sh --list, ./scripts/consistency-check.sh, scripts/protected-paths.sh.

/t-statusRead-only

A pipeline overview that never writes, comments, labels, or asks for confirmation — safe to run at any moment. Reports open initiatives and tasks, blocked/unblocked state, PR and CI/review state, and a set of warnings.

  • Lists initiatives with sub-issue completion, open tasks with blocked state, open PRs with draft/ready and review verdict, local branch/worktree state, and recent cancellations.
  • Surfaces warnings: an open PR touching a protected surface with no review, two open tasks with overlapping scope, an issue edited after its PR opened outside the expected plan exemption, a stalled branch with no PR.

Tracker/forge operations: tracker:list-initiatives, tracker:list-open, tracker:list-cancelled, forge:pr-list, forge:pr-reviews, forge:pr-checks, forge:pr-files.

Scripts: scripts/protected-paths.sh --stdin, for the protected-surface-with-no-review warning.
